# Hermes 会话数据库修复核验

适用场景：Hermes 会话检索报数据库损坏、只读、索引异常，或修复后需要确认是否真正恢复。

## 已验证的核验顺序

1. 定位 Hermes 数据库（通常为 `~/.hermes/state.db`），同时检查是否存在修复副本。
2. 对正式库和副本执行 SQLite `PRAGMA integrity_check`；必须返回 `ok`。
3. 核对表结构和关键记录数量，至少确认 `sessions`、`messages` 与 FTS 相关表存在且可查询。
4. 核对正式库与修复副本的大小、修改时间和 SHA-256；若副本就是待替换版本，确认内容一致后再继续。
5. 检查文件所有者和权限。Hermes 若以普通用户运行，数据库不能只由 `root` 持有；需要该运行用户具备写权限。优先修正为运行用户所有，并使用最小必要权限（例如 `0600`）。
6. 用 SQLite 执行一次事务性写权限探针：`BEGIN IMMEDIATE` 后立即 `ROLLBACK`，不要修改业务数据。
7. 最后通过 Hermes 自身的会话检索/浏览功能做端到端验证；只通过 SQLite 读取不能证明索引写入链路已恢复。

## 重要陷阱

- `PRAGMA integrity_check = ok` 只说明 SQLite 页面和约束基本完整，不证明进程能写入，也不证明 Hermes 的 FTS/会话检索链路可用。
- 修复工具若以 root 运行，可能生成 root-owned 数据库；这会造成“能读但不能正常维护索引”的假修复状态。
- 不要在未核对副本内容、权限和运行用户前直接覆盖正式库。
- 修复后应分别报告“数据完整性”“写权限”“应用层检索”三项结果。
