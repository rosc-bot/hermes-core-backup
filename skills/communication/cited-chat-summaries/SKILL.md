# 有来源的聊天记录总结

## 适用场景
当用户要求总结 Telegram、群聊、论坛或其他聊天记录时使用。目标是输出可核验、结构清晰、按话题归类的中文总结。

## 工作流程
1. 取得用户要求的消息数量或时间范围，并记录实际查询范围。
2. 按主题归类，避免按消息顺序逐条流水账复述。
3. 区分事实、互动和零散信息；媒体没有提取到内容时，只能说明媒体内容未读取，不得臆测。
4. 为每条重要事实附原始消息来源。公开 Telegram 群使用真实的 `https://t.me/{username}/{message_id}`；私密群使用群名和消息 ID。绝不编造链接、用户名或消息 ID。
5. 发送前核验：事实可回溯到查询结果；链接与事实一一对应；时间范围一致；折叠块完整闭合。

## 推荐输出结构
按需使用以下栏目，每个栏目独立使用 `<blockquote expandable>`：
- `📊 {群聊名称} 群聊总结 — {时间范围}`
- `话题：{具体话题}`
- `重要互动：`
- `零散信息：`
- `最终总结：`

“最终总结”必须放在最后。重要信息末尾必须有来源链接或明确的私密群消息 ID。

## 格式禁忌
- 不使用 Markdown 表格、代码框、`#` 标题、粗体或斜体。
- 不把没有来源的概括包装成已验证事实。
- 不省略用户要求的来源；如果工具没有返回生成链接所需的元数据，应先补查，仍无法补查时明确说明限制。
- 不发送内部技能维护、自我改进或后台补丁通知，除非用户明确询问。
